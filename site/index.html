carillon

Type in a box. The gaps between your keystrokes, and how long you hold each key down, become pitch and loudness — in your browser, in real time, with the Web Audio API.

Open the app Source

MIT. No install to run it. Node 20+ only for the test suite.

Nothing leaves your machine, and that is checked, not claimed

The app makes no network requests after it loads. That is not a line in this description; it is a rule enforced by verify.mjs, which scans the shipped page — index.html plus everything under src/ — and fails with a non-zero exit code if it finds any of the following:

checked fetch(...) not called anywhere in the shipped page
checked XMLHttpRequest, navigator.sendBeacon not used
checked src= / href= pointing at an http(s) URL none found
checked CDN-hosted <script src>, analytics/telemetry identifiers none found

Every one of those rules has a dedicated fixture in tests/fixtures/verify/ that deliberately breaks the page in exactly that one way, plus a test proving the rule actually catches it. A check that cannot fail is not a check.

The app is also mute-first: it is fully usable, and clearly labeled sound-off, before you click “Start sound.” That click is the only place an AudioContext ever gets created, so no sound starts without a real user gesture, and a “Stop sound” button suspends it at any time.

How the sound is built

Two real, independent signals drive it. Inter-key interval (time since your last keystroke) sets pitch: fast typing runs high, a pause runs low. The interval is log-mapped before it picks a note, because typing speed is roughly log-normally distributed, and a straight linear map would crush normal typing into a narrow band. Key dwell time (how long you held a key down) sets loudness and brightness.

Every pitch is quantized to a fixed 2-octave scale — C major pentatonic, A minor pentatonic, or D dorian, picked from a dropdown — so any two notes are consonant no matter what your typing rhythm looks like. Backspace gets its own voice: a downward chirp plus filtered noise, a full octave below anything a forward keystroke can reach, so a correction always sounds distinct from typing.

What this is not

  • Not a biometric. It does not attempt to identify who is typing, and makes no claim that keystroke rhythm reliably recognizes a person. It is an instrument.
  • Not tuned for every keyboard. The mapping was tuned by ear against one person's typing on one keyboard, and there is no claim it sounds equally good for everyone.
  • Not built for touch. This is tested against a physical keyboard; on-screen keyboards don't produce the same keydown/keyup timing.
